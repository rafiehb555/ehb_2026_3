PSS — 9-step user flow with operator handoffs

Ek hi engine (PSS) har platform ke liye verification chalata hai. Ye diagram har step ka owner dikhata hai — user, PSS engine, DMO operator, CRB. Kisi bhi step pe click karein — detailed screen khul jayega.

STEP 01

User submits entity

Seller / doctor / lawyer clicks "Send for Approval" on product / profile / listing.

STEP 02

Platform → PSS

pss-client POST /stl/submit with x-platform-key. Request enters pending state.

STEP 03

Criteria loaded

PSS loads platform + entity-type criteria_set (7–15 rules).

STEP 04

Score + STL map

Criteria met / total × 100 → L0 → L8 band. PSS cap = L4 alone.

STEP 05

Rule engine routes

Priority-ordered rules: auto-approve · franchise · CRB · reject.

STEP 06

DMO queue

High/critical risk cases land in DMO operator cockpit.

STEP 07

Franchise review

Area franchise staff reviews docs, returns decision.

STEP 08

CRB override

L8 cases + escalations. Can override franchise. On-chain hash push.

STEP 09

Webhook + live badge

Signed webhook → platform → STL badge appears to buyers.

PSS → Platform · Webhook + live badge

Step 09 — Signed webhook + STL badge live

Decision final hote hi PSS signed webhook push karta hai. Platform us ko verify karta hai (HMAC), apni DB update karta hai, STL badge product pe appear ho jata hai. Failure pe 3x exponential retry.

Webhook payload
POST gosellr-api/webhooks/pss header: { x-pss-signature: "sha256=HMAC(secret, body)", x-pss-event-id: "evt_01ht..." } body: { event: "stl.decision", entity_id: "prd_9f2a1c", decision: "approved", stl_level: 3, decided_by: "auto_standard", decided_at: "2026-04-14T21:13:48Z" }
