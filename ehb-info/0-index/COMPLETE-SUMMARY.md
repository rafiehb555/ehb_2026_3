## 3️⃣ KAISE KAAM KAREGA — Working Approach

### 🤖 Founder gives content → Claude routes automatically

```
Founder text input
   ↓
Claude reads SOURCE-OF-TRUTH.md → finds owner
   ↓
Claude reads AUTO-DISTRIBUTION-RULES.md → confirms folder
   ↓
Claude updates OWNER file (if exists) OR creates new
   ↓
Claude updates REGISTRY.json
   ↓
Claude references owner in related files (no duplication)
   ↓
Claude updates MASTER-DASHBOARD if major
   ↓
Founder approves
```

### 🔄 Auto-flow connections

```
Flow file (4-flows/) → auto-generates → Page settings (15-ui-system/)
   ↓
Page settings → generates → TypeScript code (apps/web/lib/page-settings.ts)
   ↓
Code → reads at runtime → renders pages
```

### 🌐 New industry added (8-step process)

When new industry needs to be added:

```
1. Add to 3-departments/Industries.md (master list)
2. Create 3-departments/industries/<CODE>.md (sub-spec)
3. Configure CRB checklist
4. Set AI prompts
5. Add UI fields config
6. Set compliance per country
7. Map to franchise tiers (11-franchise/)
8. Update REGISTRY.json
```

NO new infrastructure needed. Just config + adapters.

### 🔀 Data flow (per transaction)

```
USER ACTION
   ↓
UI Layer (15-ui-system/ rules)
   ↓
Action Map → API endpoint (5-specs/EHB-API-SPEC.md)
   ↓
Auth + permission check (4-flows/USER-ROLES-PERMISSIONS.md)
   ↓
STL gate check (3-departments/STL.md)
   ↓
Flow Engine routes to specific flow (4-flows/)
   ↓
Trust Core (PSS/CRB/DMO) checks
   ↓
Wallet Core (lock/escrow) operations
   ↓
Industry-specific config applied (3-departments/industries/<CODE>.md)
   ↓
AI Core (recommend/fraud/match)
   ↓
DB persist (MongoDB)
   ↓
Blockchain anchor (Polkadot batch)
   ↓
Socket.IO real-time update
   ↓
Response to UI
   ↓
Dashboard refresh (DMO single engine)
```

## 4️⃣ DATA KAISE FLOW HOGI — Auto vs Manual

### Auto-flow (no manual work needed)

| What | How |
|---|---|
| New file → REGISTRY.json | Auto-update on file create |
| New file → CONTENT-MAP.md | Auto-index headlines |
| Major change → MASTER-DASHBOARD | Auto-refresh |
| Spec change → dependent code paths | Per UPDATE-RULES.md propagation |
| Flow file change → Page settings | Auto-regenerate |
| Industry added → REGISTRY topics | Auto-add code |
| Decision locked → Audit log | Auto-append |
| Code drift detected → ehb-status.json | Auto-flag |

### Manual (founder approves)

| What | When |
|---|---|
| RULE change (architectural) | Founder + dev approval |
| New industry add | Founder approval |
| New folder create | Founder approval |
| EHBGC mint | Founder + Board (Phase-3) |
| Permanent ban | Founder approval |

### CONFIG (admin tunable, no code change)

| What | Who can change |
|---|---|
| Industry multipliers | DMO Council |
| Slashing % | DMO Council |
| Yield rate (4-6%) | Founder |
| Min STL gates | DMO Senior |
| Cooling periods | DMO Senior |
| Feature flags | Admin |
| Industry DMO mode | DMO Council |

## 5️⃣ CLAUDE AI BEHAVIOR — Hamesha Yeh Karega

When founder gives any content:

1. **Search** SOURCE-OF-TRUTH.md for topic owner
2. **If owner exists:** update OWNER, reference in others
3. **If new topic:** add to SOURCE-OF-TRUTH first, then create file
4. **NEVER** duplicate logic across files
5. **Use** AUTO-DISTRIBUTION-RULES.md for routing
6. **Separate** RULE (architectural) from CONFIG (admin-tunable)
7. **Update** REGISTRY.json + MASTER-DASHBOARD
8. **Save** decisions to audit log
9. **Show** founder summary in 6-block template (headline · visual · done · files · pending · next)
10. **Reference** related files instead of copy-paste
